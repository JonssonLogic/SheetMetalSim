# Forming test log

One row per LS-DYNA run. **Add a row before you start a run, not after** — the
point is to know afterwards which combination produced which result.

A run is defined by two halves that are set in different places:

- **Model** (`forming.k` / `model.k`, exported from ANSA) — contact type and
  `MST` come from the constants at the top of `Ansa/3D-teknik/CreateContacts.py`.
  Changing them means re-running step 4 and re-exporting.
- **Deck** (`explicit-main*.k`) — all `*CONTROL_*` settings. Variants are
  generated by `make_deck_variants.py`; each carries its own `*TITLE`, so
  `glstat`, `d3hsp` and `messag` all state which deck produced them.

```
python make_deck_variants.py
python make_deck_variants.py --out "C:/Users/CV/Desktop/Forming_test/forming" \
                             --include forming.k --endtim 0.02
```

### The geometry differs too, and it changes what MST means

**v2025 CAD**: blank, die and punch surfaces are built with **offsets** that
already account for the shell thicknesses. The contact needs no thickness
compensation, which is why that setup runs correctly with no `MST` at all.

**v2026 CAD**: die and punch are **copies** of the blank surface, coincident
with it. Nothing in the geometry accounts for the sheet thickness, so the
contact must supply it. `MST` is doing that job and is **not optional** — with
`USE_MST = False` the tools sit inside the sheet from t = 0.

So "v2025 had no MST" does not transfer. The two setups compensate for
thickness in different places, and only one of them is the CAD.

For a 1.5 mm blank with `MST` magnitude 1.6:

| | offset from the shared plane |
|---|---|
| tool contact surface, if MST/2 is used | 0.80 mm |
| blank half thickness | 0.75 mm |
| **clearance per side** | **0.05 mm** — what the "+0.1" is for |
| tool contact surface, if the full 1.6 is used | 1.60 mm |
| **over-push** | **0.80 mm** — matches the run 2 dimples |

That is why `MST_SIGN` now defaults to `+1`. The `t + 0.1` rule is clearly
written for the half-thickness convention; a negative value appears to bypass
the halving, giving roughly double the intended standoff.

### Re-ranked suspects for the run 2 dimples

**MST: the magnitude was wrong, not the sign.** Settled 2026-08-31 once the CAD
convention was understood — nothing is offset anywhere, and at full stroke the
punch coincides with the die exactly, so the contact creates the whole gap the
sheet runs in.

FORMING contacts are automatic-based, so a contact thickness projects half on
each side of the midplane. Standoff per tool = `SST/2 + MST/2`. `SST` is unset,
so LS-DYNA uses the blank's true thickness — **the sheet already supplies its
own half-thickness.** MST only has to add the clearance:

| MST | standoff | gap die..punch | penetration at t=0 |
|---|---|---|---|
| unset (tool true T1 = 1.0) | 1.250 | 2.50 | 0.500 mm |
| `t + 0.1` = 1.6 (runs 1-4) | 1.550 | 3.10 | 0.800 mm |
| **`0.1` (clearance only)** | **0.800** | **1.60** | **0.050 mm** |

The rule "plåttjocklek + 0.1" describes the **gap**, and was correct. It was
implemented as the MST *value*, which double-counts the sheet thickness and
gives roughly double the intended standoff — at either sign. That is the
3.9e6 N, and it explains "pushed way more than they should" without needing any
mesh or contact-type explanation.

**MST does not scale with sheet thickness.** It is the clearance alone.

The earlier sign experiment below is superseded — both signs were tested at the
wrong magnitude:

| | contact force on the die at t=0 | died at |
|---|---|---|
| `MST = -1.6` (run 2) | 0 N, builds gradually | t = 4.14e-3 |
| `MST = +1.6` (run 3) | **3.82e6 N** | t = 1.06e-3 |

With the die and punch coincident with the blank, a positive MST asks for a
standoff of `MST/2 + SST/2` = 1.55 mm where the meshes start 0 mm apart — and
the whole of that reads as initial penetration. The negative value evidently
suppresses that, the way it is documented to for `*CONTACT_TIED_*`. It is
undocumented for FORMING contacts but it is measured, twice. `MST_SIGN` is back
to `-1`. **Do not change the sign again on the strength of the manual alone.**

Note the arithmetic that motivated `+1` was self-consistent and still wrong —
it assumed the standoff was the goal, when the real constraint is not tripping
initial penetration. Worth remembering before trusting the next tidy derivation.

**3 + 4 together are the prime suspect for the run 2 dimples.** v2025 meshed
the tools at 4 mm with a 2.0 mm curvature floor, so tool radii were *chorded* —
smoothed to roughly what a coarse blank could follow. The tools are now resolved
to 0.25 mm while the blank's finest element went the other way, 0.5 mm → 1 mm.
That is a sharp tool against a coarse sheet, and a first-order element cannot
follow it. With node-to-surface there is no slave node in the element interior
to resist, so the sheet cuts the corner and the correction lands on the end
nodes — the dimple signature.

`ADPENE` couples these two directly: it refines the blank *against tooling
curvature*. Making the tools finer while capping `MAXLVL` lower pulls the two
apart. They need to move together.

**1 remains a suspect** for the same reason (no interior resistance), and is the
cheapest to flip.

**8 is worth a sanity check** — v2025 clamped in Z, the current model clamps in
Y. Both cannot be right for the same model, so whichever run you compare
against, confirm the clamp is actually along the blankholder's free axis.

## What we know

- **MST negative is out of spec.** LS-DYNA R16 Vol I renames `MST` to `SBST`:
  *"Optional contact thickness for SURFB surface (overrides default contact
  thickness) … it only affects the location of the contact surface."* Negative
  values are documented **only** for `*CONTACT_TIED_*`. On a FORMING contact
  `MST = -1.6` is undefined behaviour, and what it controls is exactly how far
  off the tool the sheet is held — which matches the run 2 symptom.
  `USE_MST` is therefore now `False` by default in `CreateContacts.py`.
- **Node-to-surface concentrates the penalty on single nodes**, so anything too
  deep shows as an isolated dimple rather than spread over a segment. That is
  the other difference from the setup that worked, and the next thing to flip if
  turning MST off is not enough.
- **Mass scaling, not contacts, killed run 1.** `DT2MS = -1.0E-6` needs elements
  ≥ 4.65 mm for this steel; the blank started at 4 mm and adapted to 0.5 mm.
- **`MAXLVL` is a third difference from the setup that worked**, not just contact
  type and MST. It went 3 → 2 on 2026-08-28 to control mass, which halves the
  finest blank element from 0.5 mm to 1 mm. On a tight radius a 1 mm first-order
  element cannot follow the tool, and with node-to-surface there is no slave node
  in the element interior to resist it — so the sheet cuts the corner. Treat this
  as a suspect alongside the other two.

## Refinement vs mass vs runtime

These three pull against each other. Numbers for this steel
(c = 5.17e6 mm/s) and a 4 mm starting blank:

| | finest element | mass at `DT2MS -2.5E-7` | mass at `DT2MS -1.0E-7` |
|---|---|---|---|
| `MAXLVL 1` | 2.0 mm | +0% | +0% |
| `MAXLVL 2` (current) | 1.0 mm | +35% | +0% |
| `MAXLVL 3` | 0.5 mm | **+442%** | +0% |

So deeper refinement is only affordable if `DT2MS` drops with it — which is what
`explicit-main_refine.k` does. The cost is cycles, not mass.

**`ADPFREQ` is not a constraint — hypothesis closed.** The real load case is
`ENDTIM = 0.1` with the punch travelling 17 mm at **172 mm/s**, so it closes
only **0.04 mm between adaptive checks** against `ADPENE`'s 1.0 mm look-ahead —
about 23 checks' warning before contact. (An earlier figure of 0.22 mm here was
computed from an older model at 895 mm/s and was wrong.)
`explicit-main_adpfreq.k` is therefore not worth running.

## MST: settled by the manual, 2026-09-01

**LS-DYNA R16 Vol I, `*CONTACT` General Remarks, remark 10** — found by a
colleague of the user, and it explains every measurement in this log:

> For "Forming" contact, **the surface thickness of SURFB is ignored** (SURFB
> should be the rigid tooling while SURFA should be the blank).  Furthermore,
> SURFB can be **offset away from the blank** by setting a **negative** (meaning
> opposite of the positive normal of the SURFB surface) value for SBST. This
> offsets SURFB from the surface midplane by **|SBST|/2** in the direction
> opposite to the SURFB positive normal direction.  A tool and die can be
> quickly offset (virtually, not physically) with this field.

So:

- **A positive MST does nothing.** The tooling-side thickness is ignored
  outright. Runs with `+1.6` and `+0.1` gave 3.89e6 N and 3.86e6 N at t=0 -
  identical, because both meant "no offset at all". The apparent puzzle of
  "halving the standoff changed nothing" was not a puzzle; there was no standoff.
- **The sign activates the feature**, and the offset is `|MST|/2`.
- The original rule `MST = -(t + 0.1)` was **correct in sign and magnitude**:
  `|MST|/2 = 0.80 mm`, i.e. the blank's 0.75 mm half-thickness plus 0.05 mm
  clearance. Checked against measured tool positions: blankholder +0.1 -> +0.9
  against the blank's contact surface at +0.75; die -0.514 -> -1.314. No
  over-closure anywhere.
- **Direction depends on the tool normals.** "Opposite the SURFB positive
  normal" means a tool oriented the wrong way is offset INTO the sheet. Step 2's
  orientation work is load-bearing, exactly as originally specified.
- SURFA (the blank) is not ignored and keeps its true thickness.

### What this retracts

Three conclusions in this log were wrong and are superseded:

1. "Negative MST is out of spec, only documented for TIED" - true of the
   *field definition*, but remark 10 documents it specifically for FORMING.
2. "The magnitude double-counts the sheet, MST should be 0.1" - built on a
   standoff formula that does not apply, since SURFB thickness is ignored.
3. "The binder gap is too small and no contact setting can fix it" - the gap
   measurement stands, but remark 10 *is* the mechanism for fixing it virtually.
   Positioning the tools in CAD is not required.

## The binder gap is too small for the sheet (measured 2026-09-01)

Measured from `forming.k` node coordinates, y-gap to the nearest *facing* node:

| facing pair | median gap |
|---|---|
| blankholder -> die | **0.400 mm** |
| blankholder -> blank | 0.100 mm |
| blank -> die | 0.514 mm |

**The tools are 0.4 mm apart and the sheet is 1.5 mm thick.** The blank starts
over-closed by roughly 0.8 mm on the blankholder side and 0.6 mm on the die
side. That is the 3.9e6 N at t=0, and it is why MST 1.6 -> 0.1 changed nothing:
MST moves the standoff by 0.05 mm against a 0.8 mm over-closure.

No contact setting fixes this. `*CONTROL_CONTACT IGNORE` applies to automatic
contacts; the per-contact `IGNORE` for non-automatic contacts is on the **MPP
card** and this is an SMP solve. Normal direction does not help either - FORMING
types are automatic-based and therefore two-sided, so thickness goes half on
each side regardless of which way the normal points.

Something has to open that gap to ~1.6 mm before t=0: either the tools are
positioned with the clearance (in CAD, as v2025 did, or automatically in ANSA
along the tool normals), or the shove is softened (lower `SLSFAC`, longer clamp
ramp) and accepted as an artefact. **Open - awaiting a decision.**

### Two caveats

**Added mass reaches 45.5%.** Not fatal - kinetic/internal is 2.5e-5, so
inertia is not driving the solution - but the sheet carries about half again its
real mass by the end. Dropping `DT2MS` to `-1.0E-7` would remove most of it at
roughly 2.5x the runtime. Worth doing before any result is quoted as
quantitative.

**Sliding interface energy goes negative** from t = 0.077, reaching -1.6e5 and
ending at -9.1e4 (230 of 1001 samples). Negative sliding energy usually means
contact energy is being released rather than dissipated - nodes being freed
after penetrating, or penalty energy given back. It did not destabilise this
run, and the global energy ratio is still 1.000000, but it is the one blemish
and is worth watching if the configuration changes. Compare against the total
internal energy of 6.3e5: the excursion is about 25% of that, which is not
negligible.

## Refinement made the dimples worse — which diagnoses them

Run 8 refined the blank to 0.5 mm (684 -> 4620 elements) and the dimples became
**more localised and worse**. That is a positive result, not a null one: a
resolution problem eases with refinement, whereas a **geometric singularity**
concentrates. A zero-radius corner cannot be followed by any mesh, so halving
the element size just puts a smaller element on the same discontinuity.

This is why the fix is fillets in CAD rather than anything in the solver deck.

**Fillet radius guidance.** The blank's finest element is 0.5 mm at `MAXLVL 3`.
Following a 90 degree radius needs roughly 4-6 elements around the arc, and the
arc length is about 1.57r, so:

    r >= 4 x 0.5 / 1.57  =  1.3 mm  (bare minimum)
    r  ~  2-3 mm                     (comfortable)

A fillet near or below 1 mm will still not be followed by the sheet even at
`MAXLVL 3`, and would reproduce the same dimples in gentler form. The tool mesh
is not the limit - `tools_fine.ansa_mpar` resolves curvature down to 0.25 mm.

## Suggested order

1. ~~`MST_SIGN = 1`~~ — **done, run 3, worse.** Reverted to `-1`.
2. ~~Coarsen the tools~~ — **rejected.** A coarser tool represents the tool
   less accurately, and since `ADPENE` refines the blank against *tooling
   curvature*, it would also give less blank refinement — the opposite of
   helping the sheet follow a radius. If the blank cannot follow, raise
   `MAXLVL` (with `DT2MS`) instead: `explicit-main_refine.k`.
3. If dimples remain: `CONTACT_TYPE = "FORMING_ONE_WAY_SURFACE_TO_SURFACE"`.
   Isolates difference 1.
4. `explicit-main_refine.k` — keeps the fine tools but lets the blank refine to
   0.5 mm to match them. The alternative resolution of 3 + 4: instead of
   coarsening the tools, let the sheet keep up.
5. Once the model is stable, `explicit-main_orient.k` — until `ORIENT`/`ORIEN`
   are set, LS-DYNA discards the tool orientation ANSA worked out, so any
   orientation-related conclusion before this is provisional.
6. `explicit-main_penopt4.k` last — it is a tuning change and only meaningful
   against a stable baseline.
